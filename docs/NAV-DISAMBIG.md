# AI 导航的地点消歧与偏好权重

## 为什么改

交接文档验收清单里有一行「重名地点不乱猜」，此前完全依赖语言模型自觉。用真实目录（167 条）实测，两类情况会漏：

1. 用户说「明远楼」，目录里是 `明远教学楼A~E栋` 五栋，句子里没有任何信息指明哪一栋；
2. 目录本身有重名：瑞幸咖啡 3 处、北门 2 处、南门 2 处、实验楼 2 处、长大一九五一便利店 5 处。

偏好同理：`parse_trip` 没有 preference 字段，`mode=auto` 只是取耗时最短，所以「我不想走太远」对结果零影响。

## 消歧规则

在 `parse_trip` 之后加一层确定性判断（`backend/app/place_disambig.py`），有歧义的地点不再由模型单独决定。

**族名未区分 → 列出候选**

用户只说「明远楼」，同类型同前缀的条目有 5 个，直接追问：

> 明远教学楼有5个可选位置：A栋、B栋、C栋、D栋、E栋。你要去哪里？

依据是「区分词」：某条目的某个名称或别名只有它自己拥有。说了「明远C」「明远3」即命中，不再追问。

**真实重名 → 按方位列出**

> 校园里有3个同名地点：瑞幸咖啡（偏西）、瑞幸咖啡（居中）、瑞幸咖啡（偏东）。你要去哪一个？

方位按组内较宽的一条轴排序，保证标签互不相同，不会出现两个「东北」。

**同一点位的重复节点 → 不追问**

北门两个 OSM 节点只差 10 米、南门两个差 50 米，是同一点位。80 米内同名视为同一处，只保留第一个。
同时 `demo_parse` 也合并同名命中，否则「我在北门」会被拆成起点=北门、终点=北门。

**更长的名称不属于该族 → 不误伤**

「滋兰苑餐厅」以「滋兰」开头，但它是 `building_center`，而「滋兰苑东／西」是 `parking_center`。若文本里存在以该族名开头、且不属于该族的更长名称，就不把这段文字当作族名提及。

## 偏好权重

`parse_trip` 的返回增加 `preference`：`less_walk / avoid_crowd / fastest / null`。

权重只改排序系数，普通导航仍传默认值，两条路径共用同一个 `parking_cost`：

| preference | approach | walk | occupancy |
| --- | --- | --- | --- |
| 默认（普通导航） | 1 | 2 | 5 |
| less_walk | 1 | 4 | 5 |
| avoid_crowd | 1 | 2 | 12 |
| fastest | 1 | 1 | 0 |

`less_walk` 另用「纯步行时间」在候选之间取舍；`avoid_crowd` 额外按容载率加权。回复末尾带一句加权说明，`route.ai.reason` 同步包含，便于解释。

## 改动

| 文件 | 改动 |
| --- | --- |
| `backend/app/place_disambig.py` | 新增。族分组、区分词、位置标签 |
| `backend/app/navigation.py` | `parse_trip` 增加 preference；`compute_parking` 增加可选 weights；`chat_navigation` 接入消歧与偏好；`demo_parse` 合并同名节点 |
| `backend/tests/test_nav_disambiguation.py` | 新增。14 条测试 |

`/api/navigation/chat` 的请求与响应协议未变，只多返回一个可选字段 `preference`。

## 验证

真实目录实测，无模型密钥、走内置规则：

| 输入 | 结果 |
| --- | --- |
| 我要去明远楼 | 明远教学楼有5个可选位置：A栋…E栋 |
| 我要去修远楼 | 修远教学楼有4个可选位置：一区…四区 |
| 我要去朝晖园 | 朝晖园有12个可选位置：7号公寓、8号公寓…（按数字排序，非字符串） |
| 我要去瑞幸咖啡 | 3个同名地点：偏西／居中／偏东 |
| 我在北门 | 合并重复节点，追问目的地（此前误判成「北门到北门」） |
| 我要去滋兰苑餐厅 | 不再被「滋兰」停车族误伤 |
| 我在23号宿舍楼，要去明远C栋 | 直接出路线，不再追问 |

`pytest -q` → 114 passed / 0 failed，原有 100 条零回归。

## 尚未做

- 未改 `demo_parse` 的匹配算法（子串命中），只修了同名节点合并。「我要去明远楼」能出追问靠的是新的消歧层，不是规则解析器本身。
- 目录仍是全量塞进 system prompt（167 条，约 14 KB）。
- 偏好只作用于停车排序和步行/骑行取舍，未改路网的拥挤成本。
