# 地点简称与教学楼步行通行

更新：2026-10-17。

## 搜索与缺漏地点

`GET /api/navigation/places?q=明远1` 返回明远教学楼 A 栋，且排在“明远1西侧”等停车区域之前。支持数字/中文数字、区/栋/教学楼等后缀、全角字母、常见简称和有限错字模糊匹配。楼号有输入时不跨号猜测。

明远 1—5 分别作为 A—E 栋的搜索别名；修远、鸿远支持数字与中文区号。接口每项增加 `aliases`，AI 导航的地点目录也包含该字段，负责同学应复用目录，不在模型里另猜坐标。

修远四区在 OpenStreetMap 中是带中庭空洞的 multipolygon relation，旧目录只导入了普通 way，因此漏掉。已加入真实建筑对象 `osm_relation_16871375`，来源：https://www.openstreetmap.org/relation/16871375 。坐标为建筑参考中心，非实测门位。

## 步行规则

依据负责人“教学楼内部可以穿行”的规则，新增 `backend/app/building_walk.py`：

- 以 `data/buildings.osm.geojson` 中修远、明远、鸿远的实际建筑轮廓建立步行连接。
- 从建筑内或外墙附近 18 米内的已有步行路网节点选取最多八个分布在各侧的接入点。外墙投影是模型接入点，不等同于实际已测绘门位。
- 用多边形内部可见性与最短路连接各侧，路径不跨出凹建筑边界，也不直接穿越中庭空洞。
- 仅允许 `walk`，不允许自行车或电动车借楼内抄近路；不修改数据库保存的室外路网。
- 室外停车点先接入室外道路，再通过上述接入点进入教学楼，不能直接吸附到楼内捷径。
- 步行距离和耗时包括停车点/目的地接入路网的直线距离估算。该接驳仍非测绘路径；室外人流密度成本仍适用。不能把这里的模型连接描述成实测门厅、走廊或无障碍路线。

普通导航、停车后步行、AI 工具计算和动画步行使用相同的通行规则。真实门位、楼层与内部走廊数据接入后，可以替换该参考模型，不必修改前端协议。

## 返回字段

步行路线新增 `uses_building_passage`、`building_passage_basis`；停车候选新增 `walk_distance_m`、`walking_basis`。原有 `walk_minutes` 继续表示当前路况下的预计步行分钟。前端同时展示步行分钟和米数。

可复算的无拥挤室外路网对照：修远4北到修远四区，室外绕行方案约191.2米、2.5分钟；加入楼内通行模型后约81.7米、1.1分钟。两者均计入接驳估算，不是实地实测时间；动态人流和后续路网编辑会改变结果。

测试：`backend/tests/test_place_building_walk.py` 覆盖别名排序、真实四区目录、穿行缩短绕行、禁止骑行进入楼内、凹多边形和中庭限制。

## 数据来源

OSM / ODbL，原始下载保存在 `data/osm/campus-buildings.raw.json` 与 `data/osm/campus-building-relations.raw.json`，处理后的建筑轮廓为 `data/buildings.osm.geojson`。查询范围只覆盖相关教学楼区域，不代表全校建筑目录已完整。
