## 你现在负责什么

把现有应用里的 AI 按钮升级成校园出行助手：用户自然语言表达需求 → 查询地点和停车状态 → 调用真实路线算法 → 返回建议，并把路线画在现有地图上。

你使用 WorkBuddy 的 DeepSeek 帮助写代码；识图模型固定使用 Qwen；出行助手（指路）的模型及服务商由你选择，不限定百炼或 Qwen。开发工具账号与产品 API 账号、密钥独立。视觉识别已经使用 Qwen，不需要你重新接入图像识别。完整执行要求见同目录《LLM交接-AI执行说明.md》，请把它连同最新源码交给 WorkBuddy。

## 最先完成的业务闭环

1. 用户说“从这个宿舍到某教学楼，骑车，停车后尽量少走路”。读取地图已选起终点；地点缺失时搜索，重名时展示候选，不猜坐标。
2. 查询停车状态，调用骑行路线及目的地附近停车推荐。
3. 返回推荐停车区、容载率、预计路网耗时、停车后步行时间，并在地图显示骑行段和步行段。
4. 用户追问“换个更空的”“还是少走路优先”，合并上一轮条件，重新计算排序，地图随之更新。
5. 用户问公交时，展示已有线路、站点和带时间的人数信息；候车、换乘或总耗时缺少规划能力时直接说明尚未接入。

“少走路”“更空闲”必须影响后端候选排序，不能只换一句解释。目前停车评分是：到停车区时间 + 2 × 停车后步行时间 + 5 × 容载率/100；不是已经支持任意偏好的接口。你需要与负责人约定并实现受校验的优先级/权重参数，保留默认行为。

## 接口速查

|现有接口|用途及注意事项|
|---|---|
|`GET /api/navigation/places?q=地点名`|校园地点搜索，返回 ID、名称、坐标、位置类型|
|`POST /api/navigation/route`|真实道路图上的步行/骑行路线|
|`POST /api/navigation/parking-recommendations`|目的地附近停车区联合推荐，包含两段路线、时间、评分和数据来源|
|`GET /api/parking/areas`|当前停车区及容量|
|`GET /api/parking/overview`|当前统一停车状态，识别估算与模拟数据可以混合存在|
|`GET /api/transit`|线路、站点、车辆容量和已上传人数|
|`POST /api/navigation/recommend`|已有的简单 AI 步行/骑行选择；保持兼容|

路线接口请求基本格式：`{"origin":{"longitude":经度,"latitude":纬度},"destination":{"longitude":经度,"latitude":纬度},"mode":"bike"}`；mode 只支持 walk/bike。

不要使用 `/api/parking/status` 作为识别融合状态，它仍是模拟接口。不要误用旧 `/api/routing/plan`，它仍返回 501。`/api/trips/plan` 是另一套节点 ID 规划，当前校园停车状态采用模拟数据，不作为本次应用助手默认入口。

## 统一统计口径

- 自行车、电动两轮车分开显示，并显示二轮车总数；类型不明时保留未知分类，不强行归类。
- 同区同批次多视角是联合去重估算，不能把不同视角数相加，也不能把不同时间的历史记录相加。
- 停车区周边分配给该区域的违停已包含在总数内，不能再加一次。
- 容载率 = 包含归属违停的二轮车总数 / 地图停车区容量 × 100%；允许 120% 等超过 100% 的值。容量以停车区数据为准。
- `illegal_count=null` 表示没有此分类结果，不能解释为违停 0 辆。
- 上传照片/视频识别不是实时监控；模拟数据标记“模拟”，识别数据标记“识别估算”，显示更新时间。不要加入任何人工复核、待核验或现场确认提示。
- 停车容载率不能直接当作道路拥堵数据；没有动态路权数据时不能声称已避开实时拥堵。

## 配置和协作

现有后端配置已支持从项目 `百炼.env`、`.env` 及环境变量读取；环境变量优先。现有字段是 `DASHSCOPE_API_KEY`、`QWEN_VISION_MODEL`、`QWEN_VISION_BASE_URL`，导航还支持 `NAV_AI_MODEL`、`NAV_AI_BASE_URL` 覆盖。Compose 也已配置可选 env_file。不要覆盖负责人已有密钥文件。

新助手应使用独立服务商、模型、地址和密钥配置，不与 Qwen 视觉密钥混用。可以给新助手增加独立配置，但需要同时实现读取并更新 `.env.example`，不能只在文档写变量就当作已经生效。助手的服务商、地址、模型及费用方案由你选择并写明；工具调用能力以所选服务实际联调结果为准。不要假定视觉模型的当前简单 JSON 调用等于多轮工具调用已经实现。

密钥只在后端，不进入 `VITE_`、浏览器、日志或 Git。助手查询不应触发收费的图片识别任务；直接读取已有结果。WorkBuddy 开发环境不需要拿到负责人的真实密钥，先用测试替身完成离线测试。

本地：应用 http://127.0.0.1:5174/ ，调试 http://127.0.0.1:5174/debug ，接口 http://127.0.0.1:8000/docs 。Compose：项目根目录执行 `docker compose up -d --build`，网页 http://127.0.0.1:8080/ 。本机启动和 Mac 说明以仓库现有脚本、`START-HERE-MAC.md` 为准。
