# 搜索导航、停车推荐、公交与多角度识别

## 应用页

打开 http://127.0.0.1:5174/ ，首页先显示搜索栏。搜索宿舍、教学楼或停车区后，可点击“到这里去”；也可点击搜索栏旁的路线按钮，展开起点、终点输入。两端均可搜索或地图选点。

终点800米范围内的停车区按以下成本排序：

`到停车区时间 + 2 × 停车后步行时间 + 5 × 容载率 / 100`

单位为分钟；100%容载率增加5分钟等价成本。候选必须能沿现有路网到达，优先使用道路节点关联的停车入口，没有入口则使用区域中心投影至道路。路线时间不包括入口接驳和停车操作。点击停车推荐卡可显示蓝色到停车区路线、青色虚线停车后步行路线。可独立开关停车区域、容载率提示和公交线路。

普通导航和停车推荐由后端计算。AI按钮调用百炼，从计算出的步行和骑行方案选择。停车卡片另按上述公式排序。

## 多角度标注与识别

1. 进入 /debug → 人车识别 → 可停车范围标注。
2. 上传照片或视频，选择一份素材。
3. 在“本画面归属”选择地图停车区；填写视角名、同一时刻采集批次。
4. 只画可停车范围，保存当前帧。画面应覆盖这一停车区及归属于它的周边，避免包含其他停车区。一个素材对应一个地图停车区，多个可停多边形采用并集。
5. 其他视角重复以上步骤，使用相同停车区和相同批次；跨时段使用新批次。
6. 点击“读取同区同批次已保存视角”，勾选1～6张照片或视频帧，再点击联合识别。

Qwen一次接收多幅原图和已保存的归一化区域坐标，联合估算同批次唯一车辆数，而非相加。视频仅发送所选原尺寸帧；每次最多6个视角，原始图像总大小上限24MB，不自动缩图。联合识别会调用付费API。

计数分项：自行车、电动两轮车、类型不明车辆；位置分项：区内、违停、位置不明。位置分项之和等于总数，违停已经是总数的子集，不能再次相加。该停车区周边违停归属于该区。容载率为总数除以地图停车区容量，允许超过100%。联合估算不等同于几何标定或跨摄像头轨迹跟踪。

关联区后，普通单文件识别的容量也由后端读取，前端不能覆盖。区域容量改变后，概览与推荐按新容量重算百分比。新批次替换该区的旧观察结果，不叠加跨时刻数量。无识别结果的区域继续使用明确标记的模拟状态；有识别结果显示Qwen上传估算及更新时间，均不宣称实时。

## 公交工作台

进入 /debug → 公交。点击新增线路，按行车顺序点击地图绘制折线，填写线路名和颜色。新增站点时填写站名，再点击地图放置；在线路下勾选站点，用上下箭头调整停站顺序。往返线路可分别绘制。结束后保存全部。

在所选线路添加车辆，配置总容量与摄像头ID。保存后可提交测试人数；应用页打开公交图层，可查看线路、站点以及车内人数与拥挤度。当前未自动连接摄像头或编造班次时间。

## 后端接口

| 接口 | 内容 |
| --- | --- |
| GET /api/parking/overview | 统一区域状态，count含违停，percent不封顶，附source、updated_at |
| POST /api/navigation/parking-recommendations | origin、destination、mode；返回候选、两段路线与评分 |
| PUT /api/annotations/media/{id} | 原有revision、polygons、reviewed_frames，加area_id、view_name、capture_group |
| GET /api/annotations/views?area_id=...&capture_group=... | 同区同批次已保存帧 |
| POST /api/vision/surveys | area_id、capture_group、views；异步任务，经原任务接口查询 |
| GET /api/transit | 公交线路、停站、车辆、最近车内观察 |
| PUT /api/transit | revision、stops、routes、vehicles，旧版本返回409 |
| POST /api/transit/vehicles/{id}/observations | 摄像头或测试人数上报 |

联合识别请求示例（素材ID由上传返回）：

```json
{"area_id":"停车区ID","capture_group":"2026-10-16-14:00","views":[{"media_id":"32位素材ID","time_seconds":0}]}
```

每个视角必须已保存且关联相同区域、批次。视频秒数必须精确对应已保存帧；相邻帧不自动继承区域。任务保存提交时的区域快照和批次信息，后续修改标注不改变既有任务。

摄像头模块后续识别得到车内总人数后，提交：

```json
{"count":36,"captured_at":"2026-10-16T06:00:00Z","source":"camera","camera_id":"bus-01-interior"}
```

摄像头ID必须与车辆配置一致。captured_at必须带时区，不接受超过5分钟的未来时间，也不接受相同或更早的观察。车辆容量30时36人显示120%；修改容量后自动重算。人数是当前车内存量，不是上下车人数累加；多车内摄像头需在识别端去重后上报一次。手动测试使用source=manual_test，前端明确标记测试来源。

## 存储与验证

SQLite保存标注关联、公交配置历史、车内最新观察；原素材保存在标注素材目录。使用现有scripts/backup-data.py统一备份。新功能无需增加npm包或数据库服务，仍由现有Docker Compose部署。

接口集成测试使用模拟模型回复验证容量联动、违停子集、多角度格式、采集批次、公交版本冲突与乱序观察；测试不消耗Qwen额度。
